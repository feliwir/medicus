# Addon ABI changelog

Versions refer to `MD_ABI_MAJOR.MD_ABI_MINOR`. While the major version is 0, every minor version
is a breaking change.

## 0.7 (unreleased)

- Addon manifests (ADR-0004): addons export `medicus_addon_manifest`, returning JSON with `name`,
  `version`, `target`, `provides`, `requires` and `required`. The host reads it before
  initialization to resolve dependencies and the load order.
- `medicus_addon_init` returns an `MdStatus` instead of a pointer; `MdAddonInfo` is removed (its
  fields are in the manifest).
- Registering a capability kind not listed in the manifest's `provides` fails with `MD_REJECTED`.
- Settings, users and credentials in the index (ADR-0004 §3): new index requests
  `settings_current`, `settings_revision`, `settings_history`, `put_settings`, `create_user`,
  `update_user`, `get_user`, `list_users`, `delete_user`, `put_credential`, `find_credential`,
  `list_credentials`, `delete_credential` and `prune_credentials`. `put_settings` with a revision
  that does not follow the latest one fails with the new status `MD_CONFLICT` (12).
- New host method `authenticate` (`{"secret"}` → user name or `null`): protocol addons accept the
  server's sessions and API tokens and pass the user as the call context's principal. The
  permission `admin.*` values (`admin.system`, `admin.users`, `admin.jobs`, `admin.peers`,
  `admin.events`) can appear where permissions are listed.
- New capability `MD_CAP_HTTP_ROUTES` (6) with `MdHttpRoutesVtable`: HTTP routes under a path
  prefix, mounted into the core's HTTP server. `handle` gets the request head as JSON and the whole
  body, and completes with the response body as stream and its head (`{"status", "headers"}`) in
  the stream completion's buffer, which `MdStreamCompletion` now calls `data`: the error message on
  failure, call-specific data (or nothing) on success.
- Manifests may carry `config_schema`, a JSON Schema of the addon's configuration.
- Manifest files (`<name>.addon.toml`, generated by `medicus addon manifest`) let the server
  discover addons in its search paths without loading them; the library's embedded manifest must
  match its file.

## 0.6

- Partitions (ADR-0003): index requests `query`, `locate`, `delete` and `update_extra` take a
  `partition`; instance records and locations, events (`partition`, `node`) and jobs (`partition`,
  `node`) carry one; `stored_bytes` returns `[{partition, store, bytes}]`.
- Call context (ADR-0003): `ingest` takes the JSON call context `{"node", "origin"}` instead of
  the origin; `open_instance` takes `{"context", "instance"}`; the data methods of `call`
  (`query`, `locate`, `submit_job`) take `{"context", ...}`. The core checks the caller's
  permission on the node and fails with the new status `MD_PERMISSION_DENIED` (11).
- New host methods: `metadata`, `copy_instance`, `authorize`, `permissions`, `nodes`.
- `RemoteNode` `send` requests carry the `node` (`NodeInfo`) the job was submitted through.

## 0.5

- Added `MD_CAP_REMOTE_NODE` with `MdRemoteNodeVtable`: protocol clients for peers, registered
  under the protocol name. A single JSON `call` serves `echo` and `send` (send jobs).
- Added the host methods `job_progress` (via `MdHostApi::call`), with which executors report
  progress and learn when a job was cancelled, and `submit_job`, with which protocol front-ends
  queue jobs (e.g. a `DICOMweb` send).
- Index stores gained the methods `put_job`, `get_job`, `list_jobs` and `claim_job`.

## 0.4

- Added the host function `MdHostApi::call`: host services addressed by method name with JSON
  requests and responses — `query` (complete query answers), `locate` (stored instances of a study,
  series or instance) and `peers` (configured remote nodes) — so further services need no new
  function pointers.
- Added the host function `MdHostApi::open_instance`: a read stream of a stored instance's Part 10
  file, by SOP Instance UID.

## 0.3

- Added the host function `MdHostApi::ingest`: addons (protocol front-ends) hand DICOM Part 10
  files to the core's ingest pipeline.
- Added `MD_CAP_SERVICE` with `MdServiceVtable` (`start`/`stop`): background services the host
  starts once the archive is ready.

## 0.2

- Added `MD_CAP_INDEX_STORE` with `MdIndexStoreVtable`: a single `call` taking a JSON request
  (`{"method": ..., ...}`), so that new index methods do not change the ABI.

## 0.1

Initial ABI: two-step entry (`medicus_addon_abi_version`, `medicus_addon_init`), host API (`log`,
`config`, `register_capability`), buffers, completions, pull-based streams, advisory cancellation,
and the capabilities `MD_CAP_BLOB_STORE` and `MD_CAP_EVENT_HOOK`.
